# Worked example: illustrative, generic booking-platform vendor selection

| Criterion | Weight | Vendor A | Vendor B |
|---|---|---|---|
| Cost (annual) | 30% | 8/10 — mid-tier pricing, no setup fee | 6/10 — cheaper base fee but costly add-ons |
| Reliability / uptime track record | 30% | 9/10 — strong public uptime record, references checked | 5/10 — limited track record, no references provided |
| Ease of use for staff | 20% | 7/10 — clean interface, positive trial feedback | 8/10 — slightly more intuitive in trial |
| Integration with existing tools | 20% | 6/10 — requires a workaround for accounting sync | 9/10 — native accounting integration |
| **Weighted total** | | **7.5** | **6.7** |

### Recommendation
Vendor A, primarily on reliability — the 30%-weighted reliability
criterion is the biggest score gap, and for a booking system, downtime
risk has an outsized real-world cost (lost bookings) that a small
integration convenience with Vendor B doesn't offset. Vendor B's
stronger integration score would be reconsidered if Vendor A doesn't
resolve the accounting-sync workaround within the first quarter.
