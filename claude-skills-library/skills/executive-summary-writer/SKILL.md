# Executive Summary Writer

## When to use this

There's already analysis, research, or a long document, and it needs to
become something a time-pressed reader (a client, a board member, an
investor) can absorb in under a minute and know what to do with.

## When NOT to use this

- There's no underlying analysis yet — this skill summarizes existing
  work, it doesn't generate the analysis itself. Do the analysis first
  (with whichever skill fits) then summarize it.
- The audience wants full detail, not a summary — don't compress
  something that's supposed to stay comprehensive.

## Workflow

1. **Identify the single main message.** Before writing anything, state in
   one sentence: what does the reader most need to know or decide? If
   there isn't a clear single answer yet, the underlying analysis isn't
   finished — don't paper over that by writing a vague summary.
2. **Lead with the answer (Pyramid Principle), not the process.** Don't
   open with "we analyzed X, then looked at Y, then considered Z" — open
   with the conclusion or recommendation itself. The reasoning comes
   after, to support the answer, not before it as a build-up.
3. **Structure the supporting logic as 3-5 grouped reasons**, each one
   a genuine reason for the main message — not just restating it, and not
   an unrelated fact. Each reason should be a claim, not just a topic
   ("Costs are rising faster than revenue" not "Cost trends").
4. **State what should happen next.** An executive summary that ends
   without a clear next step or ask is incomplete — even if the next step
   is "no action needed, monitor quarterly."
5. **Cut ruthlessly.** If a sentence doesn't support the main message or
   the recommended action, it doesn't belong in the summary — it belongs
   in the full document being summarized.
6. **Keep it to one page (roughly 250-400 words)** unless the user
   specifies otherwise.

## Output format

```
## [Title: the subject, not a vague label like "Summary"]

**Bottom line**: [the main message/recommendation, one to two sentences]

**Why**:
- [Reason 1, stated as a claim]
- [Reason 2, stated as a claim]
- [Reason 3, stated as a claim]

**What this means / next step**: [the recommended action or decision
needed, and by whom/when if relevant]
```

## Common pitfalls

- Burying the recommendation at the end instead of leading with it — the
  single most common executive summary mistake.
- Listing topics instead of claims ("Market trends" instead of "The
  target market is growing 12% annually, faster than our current
  capacity").
- Including process narrative ("first we did X, then Y") that belongs in
  the appendix, not the summary.
- No clear next step — leaving the reader informed but not knowing what
  happens next.

## Quality checklist

- [ ] The main message is stated in the first two sentences
- [ ] Every supporting bullet is a claim, not a topic label
- [ ] A clear next step or ask is present
- [ ] Fits on one page / roughly 250-400 words
