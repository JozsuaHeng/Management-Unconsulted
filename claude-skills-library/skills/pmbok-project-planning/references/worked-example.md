# Worked example: illustrative, generic office relocation project

### Work Breakdown Structure (top level)
1. New site fit-out
   1.1 Lease/legal finalised
   1.2 Interior design and build
2. IT/systems migration
   2.1 Network and hardware moved
   2.2 Systems tested at new site
3. Staff transition
   3.1 Communications to staff (see communication & engagement plan)
   3.2 Move-day logistics

### Knowledge area summary
| Area | Plan / cross-reference |
|---|---|
| Scope | This site only; excludes any headcount or org changes |
| Schedule | Move-day fixed by lease end date; work backward from it |
| Cost | Fixed budget agreed with finance; fit-out is the largest line |
| Quality | New site must pass a pre-move-in inspection checklist |
| Risk | See RAID log — lease/legal delay is the top risk |
| Resources | Facilities lead, IT lead, one staff-comms owner |
| Communications | See communication & engagement plan — staff need adequate notice |
| Procurement | Fit-out contractor, IT/network vendor |
| Stakeholders | See stakeholder influence map — staff, landlord, IT vendor |

This example shows PMBOK's breadth used correctly: most of the actual
depth (risk, comms, stakeholders) lives in the dedicated skills, and
this plan stays the short integrating summary rather than re-deriving
that detail from scratch.
