# OKR Drafter

## When to use this

The user has a goal (for the business, a team, or themselves) and wants
it turned into a structured objective with measurable key results for a
defined period.

## When NOT to use this

- The goal is really a single task with a deadline, not a broader
  objective needing multiple measures of progress — a simple task doesn't
  need the OKR structure.
- There's no way to measure progress at all, even roughly — flag that the
  goal needs to be made more concrete before OKRs can be written for it,
  rather than forcing vague key results.

## Workflow

1. **Write the Objective as qualitative and motivating**, not a number
   itself — it should answer "what do we want to achieve and why does it
   matter," in language that would still make sense to explain to someone
   without the underlying data.
2. **Write 2-4 Key Results per Objective**, and for each, apply this test:
   **could this key result be objectively marked done or not done, with a
   number, by the end of the period?** If the answer is unclear, it's not
   a real key result yet — push for a measurable version.
3. **Distinguish key results from tasks.** "Launch the new booking page"
   is a task (binary, no measure of degree); "Increase booking conversion
   rate from X% to Y%" is a key result (measurable, shows degree of
   progress). If every "key result" is really a task list, the Objective
   probably needs reframing around an actual outcome.
4. **Set an ambitious-but-real target for each key result** — not a
   guaranteed layup, and not a fantasy number with no basis; if a
   reasonable target isn't known yet, say so and suggest starting the
   period by establishing a baseline first.
5. **Limit to 2-3 Objectives per period** for a small business/team — more
   than that usually means nothing is actually prioritized.

## Output format

```
## OKRs: [period, e.g. Q4 2026]

### Objective 1: [qualitative, motivating statement]
- KR1: [Measurable target, from baseline to target]
- KR2: [Measurable target]
- KR3: [Measurable target]

### Objective 2: ...
```

## Common pitfalls

- Key results that are really just a to-do list ("redesign the website")
  with no actual measure of degree or success.
- Vague, unmeasurable key results ("improve customer satisfaction")
  without a number or method to track it.
- Setting either sandbagged (guaranteed) or fantasy (baseless) targets
  instead of grounded, ambitious-but-real ones.
- Too many Objectives, diluting focus rather than prioritizing.

## Quality checklist

- [ ] Each Objective is qualitative and motivating, not itself a number
- [ ] Every Key Result is genuinely measurable (a number, from baseline to
      target)
- [ ] No key result is secretly just a task with no measure of degree
- [ ] 2-3 Objectives max, each with 2-4 Key Results
