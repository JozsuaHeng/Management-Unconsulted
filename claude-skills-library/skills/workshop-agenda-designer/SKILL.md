# Workshop Agenda Designer

## When to use this

The user needs to plan a workshop — a session with a group where a
specific output (a decision, a plan, an agreed set of priorities) needs
to exist by the end, not just a discussion.

## When NOT to use this

- A regular status meeting with no specific workshop-style output
  needed — a normal agenda is enough.
- The output/objective genuinely isn't known yet — clarify that first;
  designing activities before knowing the required output produces a
  workshop that runs well but doesn't land anywhere.

## Workflow

1. **State the required end-output in one sentence before designing
   anything** — "a strategic plan" is vague; "agreed, updated
   objectives for the next planning cycle, with each objective's KPI
   defined" is a real target to design toward.
2. **Work backward from that output** to the activities that produce
   it — each agenda item should visibly build toward the stated output,
   not just be a generally-relevant topic.
3. **Design for participation, not presentation.** Long stretches of
   one person presenting to a passive room produce weak output — build
   in small-group work, structured discussion prompts, or individual
   input before group discussion (so quieter voices contribute before
   the loudest opinion anchors the room).
4. **Allocate realistic time, including breaks.** A packed agenda with
   no breathing room degrades output quality in the back half — budget
   buffer, not just the optimistic minimum per section.
5. **Write facilitation notes**, not just topic titles — what the
   facilitator actually says to open each section, how to handle a
   dominant voice or a stalled discussion, and what "done" looks like
   for each activity before moving on.
6. **Plan output capture explicitly** — who's taking notes, in what
   format, and what artifact exists at the end — a great workshop with
   no captured output loses most of its value within a week.

## Output format

```
## Workshop: [name]
Required output by end of session: [one sentence]

| Time | Duration | Section | Activity | Produces |
|---|---|---|---|---|
| ... | ... | ... | ... | ... |

### Facilitation notes
[Per section: opening prompt, how to handle common friction, what "done"
looks like before moving on]

### Output capture
[Who captures what, in what format, and what happens to it afterward]
```

## Common pitfalls

- No clearly stated required output — the workshop runs but doesn't
  land on a decision or artifact.
- All-presentation, no-participation design.
- Over-packed agenda with no buffer, degrading the back half of the
  session.
- No plan for capturing output — insights discussed live but never
  written down get lost.

## Quality checklist

- [ ] Required output is stated in one sentence before the agenda is
      built
- [ ] Every agenda item visibly builds toward that output
- [ ] Activities include real participation, not just presentation
- [ ] Time allocation includes buffer/breaks, not just optimistic
      minimums
- [ ] Output capture method and owner are explicit
