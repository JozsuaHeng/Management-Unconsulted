# Worked example: illustrative booking-platform review, 6 months post-launch

| Promised benefit | Target | Actual | Status | Action |
|---|---|---|---|---|
| Reduce booking-error rework by 3 hrs/week | 3 hrs/week saved | ~2.5 hrs/week saved | Realized (close to target) | None needed |
| Reduce missed/duplicate bookings by 1% of revenue | 1% of annual revenue | Data not being tracked consistently | Blocked | Set up a monthly error-tracking report before this can be measured |
| Improve staff satisfaction with the booking process | Qualitative — no numeric target set originally | Anecdotally positive but never measured | Not realistic to assess as stated | For future business cases: set a measurable proxy (e.g. a quarterly quick survey) for qualitative benefits, not just an assumption they'll be felt |

### Overall
The platform delivered its main quantified benefit close to target. One
promised benefit can't yet be verified because the measurement itself
was never set up — that's a process gap to fix now, not evidence the
benefit didn't happen. The qualitative benefit was stated too vaguely
to review at all, which is itself the most useful finding for how the
next business case should be written.
