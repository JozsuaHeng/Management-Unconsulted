# Plan on a Page

## When to use this

The user needs to condense a strategy, program, or function's direction
into a single page that a busy audience can absorb at a glance — for
team alignment or an executive briefing.

## When NOT to use this

- A fuller strategic analysis hasn't actually been done yet — this
  format condenses existing thinking, it doesn't replace the work of
  arriving at real priorities (use the strategic-analysis skills first,
  e.g. `swot-strategic-review`, `mece-problem-structuring`).
- The audience needs full detail, not a summary — don't compress
  something meant to stay comprehensive.

## Workflow

1. **State purpose/vision in one line** — what this function, team, or
   program exists to achieve. If it takes a paragraph to say, it's not
   focused enough yet.
2. **State current state honestly, in 2-4 bullets** — real facts, not
   spin. A "plan on a page" that oversells the starting point undermines
   its own credibility with anyone who knows the real situation.
3. **Define 3-5 priorities or pillars — no more.** This format's entire
   value is forcing prioritization; a longer list defeats the purpose
   and signals nothing was actually deprioritized.
4. **For each priority, show what changes** — briefly, across people,
   process, and systems/tools, so the priority reads as something that
   will visibly happen, not just an aspiration.
5. **Fit it on one page.** If it doesn't fit, the priorities aren't
   prioritized enough yet — cut, don't shrink the font.

## Output format

```
## [Function/team/program] — Plan on a Page

**Purpose**: [one line]

**Current state**:
- [honest fact]
- [honest fact]

**Priorities**:
1. [Priority] — People: [...] Process: [...] Systems: [...]
2. [Priority] — People: [...] Process: [...] Systems: [...]
3. [Priority] — People: [...] Process: [...] Systems: [...]
```

## Common pitfalls

- Cramming in more than 3-5 priorities, which defeats the format's
  purpose.
- Current state written as spin rather than an honest starting point.
- Vague pillars that could apply to any organisation ("excellence,"
  "innovation") instead of what this specific team is actually
  focusing on.
- Treating this as the strategic thinking itself, rather than a
  condensation of thinking already done elsewhere.

## Quality checklist

- [ ] Purpose fits in one line
- [ ] Current state is honest, not spin
- [ ] No more than 3-5 priorities
- [ ] Each priority shows what actually changes (people/process/systems),
      not just a label
- [ ] The whole thing fits on one page
