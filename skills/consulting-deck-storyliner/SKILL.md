# Consulting Deck Storyliner

## When to use this

The user has content (analysis, findings, a recommendation) and needs it
turned into a slide-by-slide outline — not the final designed slides
themselves, but the structure and message of each one.

## When NOT to use this

- The content/analysis doesn't exist yet — storyline it after the
  thinking is done, not before, or the deck will be structured around
  nothing.
- The user wants actual slide design/visuals built — this skill produces
  the outline and messages; building polished slides is a separate step
  (and PowerPoint-specific skills may help there).

## Workflow

1. **Write the storyline in one sentence first**, independent of slides —
   what is this deck arguing, start to finish? If this sentence can't be
   written cleanly, the deck isn't ready to outline yet.
2. **Break the storyline into acts** (typically 3-5): commonly
   Situation → Complication → Question → Answer → Implications, or for a
   recommendation deck: Context → Problem → Options considered →
   Recommendation → Next steps. Pick whichever act structure fits the
   actual content.
3. **For each slide, write the action title first** — a full sentence
   stating the slide's takeaway, not a topic label. "Q3 bookings fell 22%,
   driven by two controllable factors" is an action title; "Q3 Booking
   Analysis" is a topic label and tells the reader nothing.
4. **One message per slide.** If a slide's action title needs "and" to
   connect two unrelated claims, it's two slides, not one.
5. **Check the "governing thought" flow**: reading only the action titles
   of every slide, in order, should tell the whole story on its own — this
   is the fastest way to test if the storyline actually holds together
   before building any visuals.
6. **Note what evidence/visual each slide needs** (a chart, a table, a
   quote) without designing it — just flag what's needed to support the
   claim in the title.

## Output format

```
## Deck storyline: [one-sentence overall argument]

### Act 1: [name]
**Slide 1** — [Action title, full sentence]
  Evidence needed: [chart/table/data described, not designed]

**Slide 2** — [Action title, full sentence]
  Evidence needed: ...

### Act 2: [name]
...

### Storyline check
Reading just the action titles in order: [paste them as a flowing list —
if it doesn't read as a coherent argument on its own, flag which
transition breaks down]
```

## Common pitfalls

- Topic-label titles ("Market Overview," "Financial Summary") instead of
  action titles that state the actual finding.
- Two claims crammed into one slide because they're "related enough" —
  if the title needs "and," split it.
- Skipping the storyline-check step and only noticing the argument
  doesn't flow once slides are built.
- Designing visuals before confirming the storyline holds — wastes effort
  if a later logic gap forces a restructure.

## Quality checklist

- [ ] One-sentence storyline exists and is clear
- [ ] Every slide title is an action title (a claim), not a topic label
- [ ] Every slide carries exactly one message
- [ ] Reading all action titles in sequence tells the full story on its
      own
